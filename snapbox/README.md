# Snapbox OOP Project

سامانه مدیریت سفارش اسنپ‌باکس با Python و برنامه‌نویسی شی‌گرا.

## ساختار پروژه

```text
snapbox_project/
    helpers.py
    driver.py
    order.py
    delivery_system.py
    main.py
    tests/
        __init__.py
        test_driver.py
        test_order.py
        test_delivery_system.py
        test_extension.py
    peer_review/
    README.md
```

## اجرا

برای اجرای رابط متنی:

```bash
python main.py
```

برای اجرای تست‌های نوشته‌شده:

```bash
python -m unittest discover -s tests -v
```

## قرارداد کلاس‌ها

- `Driver` اطلاعات راننده، وضعیت، موقعیت و اعتبار او را نگه می‌دارد.
- `Order` اطلاعات سفارش و راننده تخصیص‌یافته را نگه می‌دارد.
- `DeliverySystem` ثبت راننده، ساخت سفارش، تخصیص، تغییر وضعیت، محاسبه هزینه و گزارش‌ها را مدیریت می‌کند.
- ویژگی‌های عمومی تعریف‌شده در صورت پروژه فقط با `@property` خوانده می‌شوند و setter عمومی ندارند.
- مقادیر مالی با `Decimal` محاسبه می‌شوند.

## قابلیت افزوده‌شده

قابلیت خلاقانه این پروژه، گزارش عملکرد راننده با متد `get_driver_report(username)` است. این متد تعداد سفارش‌های تحویل‌شده، اعتبار کسب‌شده، وضعیت فعلی و موقعیت راننده را در قالب یک دیکشنری برمی‌گرداند. اگر راننده وجود نداشته باشد، `None` برمی‌گرداند.

سه تست مستقل این قابلیت در `tests/test_extension.py` قرار دارد.

## اجرای تست قرارداد استاد

فایل `test_contract.py` باید عیناً از طرف استاد دریافت و بدون هیچ تغییری در کنار فایل‌های اصلی پروژه قرار داده شود. این فایل در این بسته ساخته نشده، چون نسخه رسمی آن در اختیار ما قرار نگرفته است.

پس از قرار دادن فایل رسمی، دستور زیر را اجرا کنید:

```bash
python -m unittest test_contract -v
```

## ارزیابی متقابل

گزارش دو ارزیابی هم‌کلاسی باید پس از اجرای واقعی تست‌ها در پوشه `peer_review` نوشته شود. این گزارش‌ها نباید از پیش و بدون اجرای تست روی مخزن هم‌کلاسی تکمیل شوند.
