# کتابخانه محاسبات عددی و ماتریسی

## فایل‌ها
- `algebra.py`: کلاس‌های `AlgebraicElement`، `Integer`، `Complex`، `Matrix` و تابع `multiply`
- `test_algebra.py`: تست‌های `unittest` (۳۷ تست)

اجرای تست‌ها:

```
python -m unittest -v
```

## ساختار وراثت

```
AlgebraicElement (ABC)
    ├── Integer
    ├── Complex
    └── Matrix
```

`AlgebraicElement` یک کلاس انتزاعی است و سه متد `__add__`، `__mul__` و `__neg__` را به‌صورت `@abstractmethod` تعریف می‌کند. هر زیرکلاس موظف است این سه را پیاده کند، وگرنه نمی‌توان از آن شیء ساخت. `Matrix` از `Integer` یا `Complex` ارث نمی‌برد، چون «نوعی عدد» نیست؛ فقط قرارداد جمع، ضرب و قرینه را دارد.

## تفاوت `@staticmethod` و `@classmethod` در این تمرین

- **`@staticmethod`** (مثل `Matrix.get_ith_row`، `Matrix.is_unit_matrix`، `Matrix.make_unit_matrix`): پارامتر `self` یا `cls` ندارد و فقط ورودی‌های خودش را پردازش می‌کند. ماتریس را صریحاً به‌عنوان آرگومان می‌گیرد، یعنی تابعی کمکی که منطقاً به کلاس تعلق دارد.
- **`@classmethod`** (مثل `Matrix.make_matrix_from_string`، `Integer.from_string`، `Complex.from_string`): پارامتر اول آن `cls` است و برای ساخت نمونه جدید به‌کار می‌رود (سازنده جایگزین). چون با `cls(...)` نمونه می‌سازد، اگر کلاسی از آن ارث ببرد، نمونه‌ای از زیرکلاس خودش را می‌گیرد.

## چرا `__sub__` فقط در کلاس پایه نوشته شده است؟

تفریق برای هر سه کلاس یک رابطه ثابت دارد: `a - b = a + (-b)`. چون `__add__` و `__neg__` در هر زیرکلاس پیاده می‌شوند، یک پیاده‌سازی در کلاس پایه برای همه کافی است. با این کار کد تکراری ندارد (استفاده مجدد از کد به کمک وراثت)، و اگر در آینده خطایی در تفریق پیدا شود فقط یک جا اصلاح می‌شود.

## تصمیم‌های طراحی

- **کپسوله‌سازی:** فیلدها با `__` خصوصی هستند و فقط با `@property` (بدون setter) خوانده می‌شوند. `Matrix.elements` یک `tuple` برمی‌گرداند و سازنده از لیست ورودی کپی می‌گیرد، پس لیست بیرونی روی ماتریس اثر نمی‌گذارد.
- **`bool` رد می‌شود:** چون `bool` زیرکلاس `int` است، `isinstance(True, int)` درست برمی‌گرداند. برای همین از `type(x) is int` استفاده شده که `bool` را رد می‌کند.
- **جمع و ضرب عدد با ماتریس در هر دو ترتیب:** `Integer.__add__` و `Complex.__add__` وقتی با `Matrix` روبه‌رو شوند کار را به `Matrix` می‌سپارند (`other + self`). جمع و ضرب اعداد جابه‌جایی‌پذیرند و نتیجه یکسان است.
- **ضرب ماتریسی:** خانه `(i, j)` حاصل‌ضرب داخلی سطر `i` از ماتریس اول و ستون `j` از ماتریس دوم است (با `get_ith_row` و `get_ith_col`). ضرب ماتریسی جابه‌جایی‌پذیر نیست، پس ترتیب حفظ می‌شود.
- **خطاها:** نوع نامعتبر ← `TypeError`، مقدار یا ابعاد نامعتبر ← `ValueError`، اندیس نامعتبر ← `IndexError`.
- **بدون `eval`:** تبدیل رشته فقط با `startswith`، `endswith`، `isdigit` و `from_string` انجام می‌شود.
- **`multiply(a, b)`:** فقط `a * b` را برمی‌گرداند و `isinstance` ندارد (Duck Typing)؛ پس با `int`، رشته و هر شیء دارای `*` هم کار می‌کند.
